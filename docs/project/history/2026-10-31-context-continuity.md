## Implemented behavior and limits

Before each new execute/repair invocation, the worker reconstructs from the stored
contract and exact baseline Git objects. Missing goal/identity/document/section or
changed prior authority produces `pcp_local_context_cannot_prove` with missing items
before the model counter/fence. Unsafe Git configuration/index remains its existing
fail-closed error. Nothing refreshes expected proof to accept drift.

The latest compact manifest and a digest/size/time entry per invocation are persisted
before dispatch. Mutable summaries and raw logs are excluded. Repairs get authoritative
check names/return codes/counts and can inspect allowed source; this is not agent-reported
verification. No schema change, budget reset, receipt reset or ownership change is added.

An already registered queued job can run in a fresh interpreter with empty chat state.
A delivery-only restart recomposes the review packet and reconciles publication without
another developer call. Running/uncertain invocations remain fenced; there is no new
mid-invocation resume or replay route. Claim recovery retains its original supported
registrar/fence rules. Non-model held verification is not converted into development.

Mandatory developer material is never silently shortened. Large prompts use stdin
through the existing bounded subprocess machinery, avoiding Linux's per-argument limit
and process-list prompt exposure. Timeout/cancellation and early-child-exit tests cover
this transport. Non-local adapters retain their existing argument contract.

PR bodies include the full task contract and immutable baseline **references**, not
full copied baseline documents. Reviewers must retrieve those exact links/sections
before assessment. This avoids GitHub body limits without claiming an excerpt is a
complete policy. Developer payload tests prove materialized constraints; review tests
prove full goal/criteria plus exact baseline references and actual diff/check evidence.
