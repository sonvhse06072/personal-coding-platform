## What this new file provides

`deploy/fullpath/compose.c3b-services.yml` is a **standalone three-service Compose definition** with a disabled-by-default `owner-gated-c3b-one-job` profile. NEVER combine it with `compose.source-only.yml` or `compose.c2-db-only.yml` and NEVER run general `docker compose up` or `docker compose down` on project `pcp-f2-fullpath`. The existing C2 DB is **external to this service file**; `pcp-f2-fullpath-private` is reused with `external: true`. The Router only joins the private network. The Executor may join a **new** GitHub egress bridge, and Runtime a **different** provider egress bridge; these new networks do not exist yet.

All service image references are **new F2 tags** pinned to the already accepted source commit, `pull_policy: never`, no build config, no host ports, non-root UID/GID, read-only root, drop all Linux capabilities, no host Docker socket, fixed F2-only mounts and individual tmpfs. Executor-only fine-grained GitHub token is loaded from its own read-only Compose secret file at process entrypoint. Runtime-only database app password is loaded from a **different** read-only file at process entrypoint; raw secrets must never enter `docker inspect`, checked-in configs or chat. Router receives no GitHub/provider secret. Runtime has its own isolated `CODEX_HOME`, writable only on the F2 credential mount. Both developer-facing Runtime and the only privileged Executor receive a bounded Git author identity supplied by the Owner, not a host Git credential-helper mount.

**Outbound-network limitation:** a regular Docker bridge with `internal:false` is **not** a GitHub- or provider-domain-only firewall. The split bridges isolate service membership but do not constitute FQDN egress restriction. The proposed cost-effective first-trial risk is to use an **issuer-limited fixture-repository-only** short-lived token on Executor, and **one F2-only model auth identity** on Runtime, after separate identity, network, TTL, scope and quota proof. Do not assert FQDN confinement without a tested proxy/firewall. If this is materially unsafe, STOP rather than granting a broad host credential.
