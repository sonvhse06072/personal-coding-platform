## Scope and why the source is deliberately small

- `deploy/fullpath/compose.c2-db-only.yml` is a **standalone C2 stage**, with the same **F2-only** Compose project and resource names but **only one service**: `fullpath-db`. Do **not** combine with `compose.source-only.yml`: its other three services remain `/bin/false`, and the old file remains byte-for-byte unchanged. No Router/Runtime/Executor start, provider network, socket, ports, cloud VM or new orchestration.
- Required image `PCP_F2_POSTGRES_IMAGE` is a locally preloaded official PostgreSQL **16** manifest/architecture-specific **exact digest** (e.g. `docker.io/library/postgres:16@sha256:<64 hex>`); no digest is known from GitHub source and this PR cannot assert a host image exists. `pull_policy:never`; no automatic pull or build. New data volume mounts under PG16's `/var/lib/postgresql/data`; the image's initial OS UID/GID and entrypoint behavior need independent attestation before mutation and post-start verification. DB max configured memory 512 MiB **excludes OS/image overhead**, not measured host usage.
- PostgreSQL official entrypoint initializes brand-new database `fullpath` as superuser `fullpath_bootstrap_admin` from a separate **owner-local secret file**. Reviewed `db-c2-init-app-role.sql` creates login `fullpath` with `NOSUPERUSER/NOCREATEDB/NOCREATEROLE/NOREPLICATION/NOBYPASSRLS/NOINHERIT`; revokes PUBLIC DB/schema privileges; grants app only CONNECT+USAGE. It does **not** install the 25 application tables or grant CREATE on schema. Secrets are mounted only in this DB container as Compose file secrets; do not keep or commit secrets in the source repository. Official init scripts run **only on empty PGDATA**; an existing F2 name/volume is a STOP, not permission to reuse/reset it.
- Source tests prove static isolation/role/parked invariants only; **not** actual Docker/PG execution or image trust.

## One bounded C2 resource step — only after gates pass

Owner-local command (from the clean reviewed PCP checkout, with the verified three `PCP_F2_*` environment variables **pointing at the exact image digest and secret-file paths**) is:

```bash
( set -euo pipefail
  docker compose -f deploy/fullpath/compose.c2-db-only.yml \
    up -d --no-deps --pull never fullpath-db
)
```

**No host command above is executed by GitHub CI or this PM.** The command creates **at most** this DB container, its one new named volume, and its one private network under Compose `pcp-f2-fullpath`. Operator must not proceed if target resources preexist. Never pass the F2-only service names to generic legacy PCP lifecycle commands.

## Mandatory post-start independent proof — do NOT activate Engine

- Inspect exactly the created container, volume and network, record full IDs, Compose/F2 ownership labels, exact image ID/digest, OS UID/GID and writable volume target. Confirm no host port/socket, network `internal:true`, no unexpected mounts/containers; don't publish raw Docker inspect/environment (secrets may appear). A healthy `pg_isready` alone is **not** bootstrap/privilege proof.
- From **that exact DB container only**, use `docker compose -f deploy/fullpath/compose.c2-db-only.yml exec -T fullpath-db psql -X -v ON_ERROR_STOP=1 -U fullpath_bootstrap_admin -d fullpath ...` to query `pg_catalog.pg_roles`, `pg_database`, `pg_namespace`, `pg_class`, `pg_stat_activity`, and grants. Verify distinct roles, actual admin-vs-app flags, public revocations, app CONNECT/USAGE but **not CREATE**, fresh user-relation count 0, no PCP durable `cp_*` objects/rows, no foreign project identity; verify app password authentication separately over TCP *inside* the isolated DB container without printing the secret. Record sanitized counts/booleans only. SQL bootstrap role presence by itself is not sufficient.
- No application migration/schema install under this PR: the 25-table installer and indexes/sequences/trigger/grant manifest are **not implemented**. A different reviewed F2-only schema installer with exact DDL and a real pre/post attestation is mandatory before any future Engine startup.
- On unexpected objects, bad privileges or any uncertain ownership: **STOP**. An isolated `docker compose -f deploy/fullpath/compose.c2-db-only.yml stop fullpath-db` is allowed for a verified F2-only container; preserve the volume/logs for review. Cleanup/removal only with exact created ID/label manifest, proven zero user data and scoped Owner decision; never `docker system prune`, `docker compose down -v`, generic resets or deletion of unrelated resources.
